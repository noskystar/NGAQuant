## 1. 问题定义

### 1.1 当前问题
- **漏掉**：硬编码字典仅覆盖 ~100 只常见股票，A 股 5000+ 只大部分不在字典中
- **误报**：6 位数字可能误匹配电话号码/编号；中文短词（如"海尔"）在非股票语境下被误提取
- **情感不绑定**：当前情感分析是帖子级的，无法判断"某只股票"被看涨还是看跌
- **界面简陋**：股票仅显示名称+提及次数，无情感倾向、无价格、无交互

### 1.2 目标
- 覆盖全部 A 股（5000+只）
- 准确提取帖子中提到的股票（名称、代码、拼音缩写）
- 将情感分析绑定到具体股票，给出每只个股的看涨/看跌比例
- 改善界面展示（股票卡片、批量分析、交互过滤）

### 3.1 StockExtractor（股票提取器）

**文件**: `src/analyzer/stock_extractor.py`（重写）

**Layer 1 - 代码匹配**:
- 正则: `(?<![\d])(600|601|603|605|688|000|001|002|003|300|301)\d{3}(?![\d])`
- 匹配到的代码通过 `code_map` 验证有效性
- 输出置信度: `high`

**Layer 2 - 名称匹配**:
- 常见股票：本地硬编码字典快速匹配（约100只，O(1)）
- 冷门股票：通过 `name_map` 索引匹配，akshare 实时查询补全
- 支持中文名称、拼音缩写
- 输出置信度: `medium`

**Layer 3 - LLM 验证**:
- 仅对 `confidence == "medium"` 的结果执行
- Prompt 模板:
  ```
  以下文本中提到的'{stock_name}'是否指A股上市公司？
  只回答YES/NO，如果是股票请给出6位股票代码。
  文本: {context}
  ```
- 验证通过 → `confidence` 升级为 `"verified"`
- 验证失败 → 从结果中移除（误报过滤）

### 3.2 StockSentimentAnalyzer（股票级情感分析）

**文件**: `src/analyzer/sentiment.py`（增强，新增类）

**数据模型**:
```python
@dataclass
class StockSentiment:

    bullish_posts: int         # 看涨帖子数
    bearish_posts: int         # 看跌帖子数
```

**情感绑定策略**:
- 滑窗粒度：股票名称前后 50 个字符
- 单帖去重：一只帖子中多次提到同一只股票，只计一次情感

## 5. 错误处理

| 场景 | 处理策略 |
|------|---------|
| akshare 加载失败 | 降级到内置字典（100只常见股）+ 打印警告日志 |
| LLM API 超时/限流 | 跳过 LLM 验证层，返回代码匹配 + 名称匹配（medium 置信度） |
| 帖子内容为空/过短（<15字） | 跳过分析，标记为 "内容不足" |
| 提取到 0 只股票 | 界面显示 "未检测到股票提及"，不报错 |
| 价格获取失败 | 卡片隐藏价格/涨跌幅，其他信息正常显示 |
| 全部分析失败 | 界面显示错误提示，保留上一次成功结果 |

## 7. 性能预估

| 操作 | 预估耗时 | 优化手段 |
|------|---------|---------|
| 加载 5000+ A 股字典 | ~2s（一次性） | 启动时加载，缓存在内存 |
| 代码匹配（单帖） | <10ms | 纯正则，无 I/O |
| 名称匹配（单帖） | ~50ms | 内存索引，无需 I/O |
| LLM 验证（单帖，最多5只） | ~500ms | 批量请求，一次验证多只 |
| 情感分析（单帖） | ~300ms | 复用已有 8 线程并发优化 |
| **总耗时（单帖，10只股票）** | **~1s** | - |
| **批量分析（10帖）** | **~5-8s** | 并发处理 |
